# Map Contract

## Territory

This map describes the privacy-safe `CRHS-042 / 2026-07` monthly-close workspace in `../demo-territory/client-workspace/`. It maps the durable nouns, the one proven movement connecting them, and the first-order effect of changing each noun. Client identity and values are synthetic; the handoffs model recurring bookkeeping operations.

It excludes accounting advice, transaction values, credentials, tax information, payroll data, diagnosis, and implementation recommendations.

## Universes

- `live`: currently written, read, or used to make an operational decision.
- `leftover`: intentionally retained but no longer the primary path.
- `ghost`: named or filed but not wired. Never implement against it.

`UNKNOWN` is a query result, not a universe. An unverified candidate remains `status: stub` until evidence places it in a universe.

## Name collisions

- **Client** means this workspace boundary, not a contact person or legal-entity record.
- **Statement** means a source document, not a generated financial statement.
- **Complete** is ambiguous. Use `received`, `review-ready`, or `approved` explicitly.
- **Reviewed** is not `approved`. Approval requires an explicit approval-register row.
- **Owner** means the active assignee on the live object, not the file owner.
- **Missing Documents Tracker** names a ghost workbook; the live object is `Exception`.

## Reading contract

1. Start in `CLAUDE.md`.
2. Route through `effects/CONTEXT.md` for a change question.
3. Open one primary object card.
4. Follow one `See` citation into subject source.
5. Open another card only if the first card's relationship requires it.
6. Stop at first-order impact.

## Authority

Subject source wins over map. Within source, explicit registers and current rules win over filenames, folder names, and retained notes.
